# 数据管理、备份与 WebDAV 同步

设置侧栏顶部的“数据管理”包含“导入与导出”“备份与恢复”“云同步”三个标签页。所有数据库、压缩包和 WebDAV 请求都由主进程/Rust 层处理，渲染进程只收到脱敏状态。

## 导入与导出

1. 打开“数据管理 → 导入与导出”。
2. 默认导出全部可移植分类，生成 `.snow-config` 文件。
3. 默认不包含 API Key、MCP env/headers、代理密码、Cookie、SSH 凭据或设备路径。
4. 如果勾选“包含敏感配置”，必须设置导出密码。该包使用 Argon2id 派生密钥和 AES-256-GCM 加密，不能恢复密码。
5. 导入时先校验版本、路径、大小和 SHA-256，再创建 `pre-import` 快照，在单个 SQLite 事务中合并或替换所选分类。

导入包中的工作区绝对路径、SSH 路径和系统凭据不会被跨设备覆盖。导入失败或密码错误不会执行数据库写入；导入前生成的安全快照可用于回退。

## 数据库快照与自动备份

“备份与恢复”使用 SQLite Online Backup API，因此运行中 WAL 中已提交的数据也能进入一致性副本。每个 `.snowbackup` 包包含：

- `manifest.json`：格式、应用版本、schema、创建时间、触发原因、范围和文件 hash；
- `database/snowapp.db`；
- 默认包含的 `database/archive.db`。

可以启用自动备份，选择每 6 小时、每 12 小时、每天或每周，并保留 3–100 个快照。自定义备份目录、`archive.db` 范围、导入前和恢复前安全快照均在此页保存。当前版本不把附件、checkpoint、upload、图片库和插件运行时目录加入数据库快照。

恢复步骤是可中断的：应用先校验包并创建 `pre-restore` 快照，将目标写入 staging 和 `pending-restore.json`，然后重启。下一次启动会在数据库连接初始化前校验 staging、备份当前数据库、清理 WAL/SHM、替换文件并运行现有 schema migration。初始化失败会使用 rollback 副本恢复原状态。

## WebDAV 云同步

1. 输入 HTTPS WebDAV 地址、远端目录、用户名和 WebDAV 密码。
2. 设置独立的同步加密密码；该密码不上传服务器，也不通过 preload 返回渲染进程。
3. 选择“配置同步”（推荐）或“完整数据库镜像”。配置同步适合多台设备日常使用；镜像模式包含主库和归档库，拉取后需要重启。
4. 默认手动同步；需要时开启 15、30 或 60 分钟自动同步。
5. 先测试连接，再点击“立即同步”。冲突时自动同步暂停，选择保留本地、使用远端或分别保留双方对象。

远端布局为 `remoteRoot/snow-app/v1/`，对象按 SHA-256 内容寻址。远端对象始终先加密；`state.json` 使用 revision 与 ETag 条件写入。服务端不提供 ETag 时会显示“弱冲突保护”，并通过 revision 二次读取降低静默覆盖风险。401/403、断网、412 和 507 错误会保留本机有效数据，并在状态区显示最近错误。

WebDAV 默认拒绝 HTTP。只有明确打开“允许不安全 HTTP”后才允许不加密连接；生产环境应使用 HTTPS。忘记同步加密密码无法恢复远端对象。

## 发布迁移说明

本功能首次引入独立的 `manifest v1`、`.snow-config`、`.snowbackup` 和 `userData/data-management/` 存储域。升级时不会自动导入旧版第三方配置，也不会自动上传已有数据库；首次使用前建议先手动创建一个快照。当前 schema 为 31，应用启动仍按正常迁移流程处理数据库。

不跨设备同步浏览器密码、Cookie、SSH 私钥、系统密钥、插件私有目录或绝对 workspace 路径。附件增量同步、远端对象垃圾回收和逐条会话合并不属于首个版本。
